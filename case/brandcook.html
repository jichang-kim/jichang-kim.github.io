CASE STUDY 02 · PO / 0→1

가맹본부의 페인포인트에서
B2B 전용 플랫폼 '브랜드쿡'까지

㈜식자재쿡 · CSO/PO서비스 이원화 · 신규 플랫폼 런칭기술연구부 6인 개발 리드

문제 정의

B2C 식자재 유통을 운영하며 발견한 것은 프랜차이즈 가맹본부라는 별개의 고객이었습니다. 소규모 가맹본부는 ① 낮은 구매력(Buying Power) 탓에 대기업 3PL과 10%대 물류수수료로 계약하고 ② 가맹점 평균 매출 대비 차액가맹금 비율이 상승하며 본부–점주 갈등이 구조화되고 있었으며 ③ 데이터 기반 관리 도구가 없어 발주·정산이 수기에 머물러 있었습니다. 기존 B2C 화면 하나로는 이 고객을 담을 수 없었습니다.

가설

"가맹본부와 가맹점주에게 전용 화면과 전용 데이터를 분리 제공하면 — 같은 유통 인프라 위에서도 본부의 지불의사가 생기고, 홍보·입점이라는 새 수익 채널이 열린다."

실행 — 기획에서 출시까지

  • 서비스 이원화 설계 — 식자재쿡(B2C·개인점주)과 브랜드쿡(B2B·가맹본부/가맹점주)으로 제품 라인 분리, 프랜차이즈·로컬 커뮤니티 브랜드 대상 전용 서비스 정의
  • 가맹본부용 웹 대시보드 기획·출시 — 타겟별 맞춤 대시보드로 본부가 가맹점 발주·정산 현황을 데이터로 관리하게 제공
  • 기술연구부 6인 개발 프로젝트 리드 — 요구사항 정의, 우선순위 조율, 출시 검수를 PO로서 직접 수행
  • B2B 홍보구좌 수익모델 설계 — 프랜차이즈 브랜드 홍보구좌를 플랫폼에 구현해 구독·유통 외 수익 채널 확장
  • 파트너 얼라이언스 연동 — "실제 외식업자에게 도움이 되는가"를 기준으로 업체를 선별해 입점 즉시 실행, 토스플레이스·KT하이오더 등과 협업·MOU

러닝

같은 인프라라도 고객별로 화면과 데이터를 분리하는 것만으로 지불의사가 달라진다는 것을 숫자로 확인했습니다. B2B 제품의 핵심은 기능의 수가 아니라 "이 대시보드를 회의 자료로 쓸 수 있는가"라는 데이터 신뢰였고, 그래서 기능 추가보다 데이터 정합에 개발 우선순위를 배정한 것이 유효했습니다.

내가 직접 한 범위

PO로서 문제 발견 → 서비스 이원화 결정 → 대시보드 요구사항 정의 → 개발(6인) 우선순위 조율 → 출시·검수의 전 과정을 담당했습니다. 홍보구좌 수익모델과 파트너 선별 기준도 직접 설계했습니다. UI 구현은 기술연구부, 파트너 실무 협상은 영업 조직과 협업했습니다.
